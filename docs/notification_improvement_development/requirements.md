# 要件定義書（通知機能改良）

## 1. 背景
[plan3.md](../../plan3.md)に記載の通り、[plan2.md](../../plan2.md)で実装した
Discord Webhook通知機能について、以下2点の改良を行う。

1. [review.md](../notification_function_development/review.md)で指摘された
   🟠重要な問題1点・🟡軽微な問題5点への対応
2. 動体検知通知のスナップショット撮影タイミング・送付回数の見直し

本書は[既存のrequirements.md](../notification_function_development/requirements.md)・
[design.md](../notification_function_development/design.md)に対する**変更点・追加点のみ**を
記載する差分ドキュメントである。本書に記載のない既存要件（通知タイミングの基本方針、
Webhook URLの環境変数管理等）はそのまま有効とする。

## 2. review.md指摘事項への対応範囲
全件（🟠1点＋🟡5点）を本改良で対応する。

| No. | 指摘内容 | 対応方針 |
|---|---|---|
| 🟠#1 | `config.py`の`enabled`が`bool()`変換で文字列の型ミスを検知できない | `isinstance(value, bool)`による明示的な型検証ヘルパーを導入する |
| 🟡#3 | `notifier.py`の通知スレッドが`daemon=True`のため終了時に送信が中断される可能性 | `main.py`の`finally`ブロックで進行中の通知スレッドを短いタイムアウト付きで`join()`する |
| 🟡#4 | エラーログにHTTPステータスコード等の詳細が残らない | `HTTPError`発生時に`e.response.status_code`をログへ含める |
| 🟡#5 | `config.toml`に`enabled = true`がデフォルトでコミットされており、`.env`未設定時に初見ユーザーが混乱しうる | READMEのセットアップ手順に「`.env`の準備が必須」であることを明記する |
| 🟡#6 | `main.py`のエラーメッセージの文字列結合が読みにくい | 文字列の間に読点・スペースを補い可読性を改善する |
| 🟡#7 | `tests/test_notifier.py`のスレッド判定がCPython実装依存（`name.startswith("Thread-")`） | `thread.daemon`の判定のみに簡略化する |

※`config.py`の🟠#1対応は、[review.md](../notification_function_development/review.md)の
ユーザー判断（2026-06-26）で「動体検知時の画像送信の改良と同時に対応する」と保留されていた
事項であり、本改良がその対応タイミングとなる。

## 3. スナップショット撮影タイミング・送付仕様

### 3.1 送付タイミング
- 検知開始時に**即時1枚**送信する（既存挙動を維持）。
- 検知が継続している間（クールダウン未経過の間）、**一定間隔（デフォルト3秒）**ごとに
  追加でスナップショットを撮影・送信する。
- 検知終了（クールダウン経過による`recorder.stop()`）時点での追加送信は行わない
  （スコープ外。既存方針を維持）。
- 送信間隔は`config.toml`の`[notification]`セクションで変更可能とする
  （具体的なキー名は設計フェーズで決定）。
  　※防犯カメラとして使用するユースケースが決まっていないため、
  　　検知した対象をユーザーが認知するのを優先し、検知直後に画像w送付する。

### 3.2 送付回数の上限（レート制限）
- 「検知1回につき1通のみ」という既存の制約は撤廃し、検知継続中は3.1の間隔送信を行う。
- Discordのレート制限・通知過多を防ぐため、**一定時間内に送信できる通知数の上限**を設ける。
- 上限の**時間窓（秒）・上限通知数**はいずれも`config.toml`で設定可能とする
  （デフォルト値は設計フェーズで提案し、ユーザーと合意する）。
- クールダウン中の再検知も、検知継続中の連続送信として3.1・3.2の対象に統一して扱う
  （「再検知」という概念は別途設けない）。
  　※画像送付のレートを可変にしたため、
  　　上限も変更可能にすることでDiscordのwebhookのデータ制限に合わせることを可能にする。

### 3.3 上限到達時の挙動
- 上限に達した場合、Discordへの送信は**スキップ**する。
- スキップした旨は**標準エラー出力にログを残すのみ**とし、Discordへの代替通知・
  まとめ送信は行わない（実装をシンプルに保つため）。
  　※画像送付レートや、送付レートの上限を手探りで変更する見込みなので、上限到達時の挙動は、今は実装しない。
  　　実用上の不都合があれば、この挙動も変更する可能性あり。

## 4. 非機能要件
- 通知処理（HTTP送信・レート制限判定）はメインループ（検知・録画処理）の動作を
  妨げないこと（既存方針を継続）。
- Webhook URLなどの機密情報をリポジトリにコミットしないこと（既存方針を継続）。
- `config.toml`への項目追加・型検証強化（🟠#1）は、既存の`config.toml`記述
  （`true`/`false`のTOMLブールリテラル使用）であれば後方互換性を保つこと。

## 5. スコープ外（本改良では対応しない）
- 検知終了時の追加通知
- 上限到達によりスキップした通知の、上限解除後のまとめ送信
- 送信失敗時のリトライ機構（[既存requirements.md 2.4](../notification_function_development/requirements.md)の方針を継続）

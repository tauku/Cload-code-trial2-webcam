# 設計書（Windows防犯カメラ）

[要件定義書](requirements.md)で合意した要件を実現するための設計をまとめる。

## 1. 技術選定

| 項目 | 選定 | 理由 |
|---|---|---|
| カメラ制御・画像処理 | OpenCV (`opencv-python`) | USBカメラ入力(`VideoCapture`)、動体検知（フレーム差分）、ライブビュー表示(`imshow`)、録画(`VideoWriter`)を1ライブラリで一貫して扱え、Windows上での実績も豊富 |
| 設定ファイル形式 | TOML（`config.toml`） | Python 3.11+標準の`tomllib`で追加依存なく読み込める。pyproject.tomlと記法が統一され可読性が高い |
| 録画ファイル形式 | MP4（コーデック`mp4v`） | OpenCVの`VideoWriter`でWindows上でも追加コーデック導入なしに動作する組み合わせ |

## 2. アーキテクチャ（モジュール構成）

`src/webcam_security/` 配下に以下のモジュールを配置する。

```
src/webcam_security/
├── __init__.py
├── main.py            # CLIエントリポイント。各モジュールを統合するメインループ
├── config.py          # config.tomlの読み込み・検証
├── camera.py          # cv2.VideoCaptureのラッパー（オープン/フレーム取得/解放、切断検知）
├── motion_detector.py # フレーム差分による動体検知（感度パラメータを受け取る）
├── recorder.py        # cv2.VideoWriterによる録画開始/停止・ファイル書き出し
├── live_view.py        # cv2.imshowによるライブビューウィンドウ表示
├── storage_cleaner.py  # 保持期間（既定7日）を超えた録画ファイルの自動削除
└── notifier.py         # （将来追加予定・MVPでは未実装）検知イベントの外部通知
```

依存関係: `main.py` が各モジュールを呼び出すオーケストレーター。
他モジュール間の直接依存は持たせず、`main.py`経由でデータ（フレーム、検知結果）を受け渡す。

### 2.1 メインループの処理フロー
1. `config.py`で`config.toml`を読み込む（検知感度・保持日数・保存先ディレクトリ等）
2. `camera.py`でUSBカメラをオープン
3. ループ処理:
   - フレームを取得
   - `live_view.py`でフレームをウィンドウに表示
   - `motion_detector.py`で動体検知を実行
   - **検知開始/検知終了**のタイミングで`recorder.py`の録画開始/停止を呼び出す
     （検知が一定時間途切れたら録画停止。既定5秒、設定可能）。
     この「検知開始/検知終了」のタイミングは§7で述べる通知機能の拡張ポイントでもある
   - 起動時および一定間隔ごとに`storage_cleaner.py`で保持期間超過ファイルを削除
4. `q`キー押下、またはCtrl+C（`KeyboardInterrupt`）でループを終了し、カメラとウィンドウを解放する

## 3. データ設計

- 録画ファイルの保存先: 既定で`recordings/`ディレクトリ（`config.toml`で変更可能）
- ファイル名: 検知開始時刻から生成する `YYYYMMDD_HHMMSS.mp4`
- 追加のメタデータDB等は持たない。ファイル名のタイムスタンプを唯一のメタデータとする（MVPの非機能要件で十分なため）

### config.toml の項目例
```toml
[detection]
sensitivity = 25      # フレーム差分の閾値（小さいほど高感度）
cooldown_seconds = 5  # 検知が途切れてから録画停止までの待機秒数

[storage]
directory = "recordings"
retention_days = 7

[camera]
device_index = 0
```

## 4. 異常系設計

| 異常 | 挙動 |
|---|---|
| カメラ切断・オープン失敗 | `camera.py`で例外を捕捉し、エラーログを出力してプログラムを安全終了する（自動再接続はMVPでは行わない） |
| 録画書き込み失敗（ディスク容量不足等） | `recorder.py`で書き込み失敗を検知したらエラーログを出力し、録画を中断してメインループは継続する（ライブビューは継続可能） |
| `config.toml`の値が不正 | `config.py`で読み込み時に検証し、不正な場合は起動時にエラーを出して終了する |

## 5. セキュリティ・プライバシー設計

- 録画データはローカルディスクの`recordings/`配下にのみ保存し、暗号化やアクセス制御の追加実装はMVPでは行わない
  （要件定義でスコープ外と合意済み）。OSのファイルアクセス権限（ユーザーのホームディレクトリ配下）に委ねる。

## 6. 要件との対応確認
- 動体検知時のみ録画: §2.1で実現
- 検知感度を設定ファイルで調整可能: §3 `config.toml`の`sensitivity`
- ライブビュー表示: §2.1, `live_view.py`
- 通知なし（MVP）: §7の拡張ポイントを残しつつ、`notifier.py`はMVPでは実装しない
- CLIで手動起動/停止: `main.py`を`uv run python`で起動、Ctrl+C/`q`で停止
- 7日で自動削除: `storage_cleaner.py`, `retention_days`
- USBカメラ1台のみ: `camera.py`は単一`device_index`のみを扱う

## 7. 将来の拡張ポイント: 通知モジュール

開発完了後、検知時の外部通知（デスクトップ通知/メール等）を追加する予定があるため、
以下の通り拡張の余地を設計に残す（MVPでは`notifier.py`自体は実装しない）。

- **挿入箇所**: §2.1のメインループにおける「検知開始/検知終了」のタイミング。
  このタイミングは録画開始/停止の呼び出しと同じ場所にあるため、
  通知機能を追加する際は同じ箇所に`notifier.通知する()`相当の呼び出しを追加するだけでよい
- **想定インターフェース**: `notifier.py`に検知イベント（開始時刻・カメラ情報程度）を渡す
  関数または通知方式ごとのクラス（例: デスクトップ通知用、メール通知用）を想定する。
  `main.py`は具体的な通知方式を知らず、`notifier`モジュールに委譲する形にすることで、
  通知方式の追加・変更が他モジュールに影響しないようにする
- **設定**: 通知の有効/無効や通知先（メールアドレス等）は`config.toml`に
  `[notification]`セクションを追加して管理する想定（MVPの`config.toml`には記載しない）
- 上記以外（録画ファイル形式、保存ディレクトリ構成等）は通知機能追加によって
  変更が生じない設計になっている

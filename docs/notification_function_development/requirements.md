# 要件定義書（Discord通知機能）

## 1. 背景
[plan2.md](../../plan2.md)に記載の通り、動体検知時のスマートフォンへの通知手段として
Discord Webhookの採用が決定済み。本書では通知機能の具体的な機能要件・非機能要件を定める。

## 2. 機能要件

### 2.1 通知タイミング
- **動体検知開始時のみ**通知する。検知終了時の通知は行わない。
　※選択理由　検知時に画像を送信するので、検知終了時の通知にメリットを感じないため。

### 2.2 通知内容
- 検知時刻・カメラ情報程度のテキストに加え、**検知時のスナップショット画像を添付**する。
　※選択理由　防犯カメラなので、動体検知で何が動いたのか確認できる必要があるため

### 2.3 Discord Webhook URLの管理
- Discord Webhook URLは**環境変数**（例: `DISCORD_WEBHOOK_URL`）で管理する。
- `config.toml`は現在git管理対象（`.gitignore`対象外）のため、機密情報は記載しない。
- `config.toml`の`[notification]`セクションには、通知の有効/無効など**非機密設定のみ**記載する。
　※選択理由　手作業であれば、労力削減のためsettingsに直打ちすると思うが、今回はClaude Code作成なので、よりセキュリティのしっかりした方法を選択

### 2.4 送信失敗時の挙動
- Webhook送信が失敗した場合は**ログに記録するのみ**とし、リトライは行わない。
- 通知処理の失敗・遅延が**録画・検知などの主機能の動作を妨げない**こと。
　※選択理由　通信失敗時のリトライ機能を付けると、実機でのテストが大変になるため。
　　また、ハードウェア(windowsPCとUSBカメラ)の都合上、防犯カメラに再送機能を設けても、有効に機能はしないと考えたため。

## 3. 非機能要件

### 3.1 主機能への影響
- 通知処理（HTTP送信）はメインループ（検知・録画処理）の動作を妨げないこと
  （具体的な実装方法は設計フェーズで検討）。

### 3.2 セキュリティ
- Webhook URLなどの機密情報をリポジトリにコミットしないこと。

## 4. スコープ外（将来検討事項）
- 検知終了時の通知
- チャットボット化・双方向通知（[plan2.md](../../plan2.md)の将来拡張を参照）
- 送信失敗時のリトライ機構

## 5. 合意状況
上記はユーザーへのヒアリング結果に基づき合意済み。次フェーズ（設計）にて、
`notifier.py`の実装方法、環境変数の読み込み方法、`config.toml`の`[notification]`セクションの
具体的な項目を検討する。
